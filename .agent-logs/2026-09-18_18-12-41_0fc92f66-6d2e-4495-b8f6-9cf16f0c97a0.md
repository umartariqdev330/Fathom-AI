## 1. What was built

**Meetly AI** — full-stack, running locally right now. FastAPI + SQLAlchemy + SQLite behind React 19 + TypeScript + Vite + Tailwind v4.

Nine routes: dashboard, meetings list, meeting detail, search, calendar, highlights, settings, public share page, 404. Seven API routers covering meetings, action items, highlights, search, clips, calendar and recordings.

## 2. What is fully functional

- **Meeting detail** — player and transcript sync both directions: playback moves and highlights the active transcript line; clicking a line seeks the recording. Highlights render as coloured markers on the timeline. Verified at 11:24 on the 58-minute call.
- **Transcript** — speaker-attributed, in-meeting search with match count and highlighting, copy, download, star-to-highlight on any line.
- **AI summary** — overview, key points, decisions, topics, insights.
- **Action items** — toggle, add, edit, delete; verified persisting to the API.
- **Highlights** — create from a transcript line, delete, play from the exact moment, share as a clip; cross-meeting page filtered by category.
- **Search** — across transcripts, titles, summaries, action items, highlights, participants. `semantic` returns 11 hits across 5 meetings; results deep-link to the timestamp.
- **Clip sharing** — created a clip, opened `/share/<token>`, it renders with its own transcript and no app chrome.
- **Simulated recording** — platform → record → stop → pipeline → a real meeting, summarised at that moment by the AI service.
- Light/dark themes, mobile at 375px, no console errors, production build at 114KB gzipped.

**Seed data:** 8 meetings, 234 transcript segments, 30 highlights, 34 action items, 5 upcoming. The architecture review is 8 people over 58 minutes — the case the brief singles out. The meetings share a cast and a storyline that runs between them, so cross-meeting search has something real to find.

## 3. What is simulated

The recording bot, audio/video capture, calendar OAuth, and accounts. Playback is a virtual transport running at the meeting's real duration rather than a `<video>` — a 15-second stock clip against a 58-minute transcript makes every timestamp a lie and breaks the sync that's actually worth showing. All documented in the README and visible in-product.

## 4. Run it locally

```bash
cd backend && pip install -r requirements.txt && python seed.py && uvicorn app.main:app --reload --port 8000
```

```bash
cd frontend && npm install && npm run dev
```

## 5. Deployment status — not done, and it needs you

Configs are committed (`render.yaml`, `frontend/vercel.json` with the SPA rewrite, `.env.example`), and the backend seeds itself on first boot so a fresh deploy is never empty. But deploying needs your Render and Vercel accounts, and `gh` isn't installed here, so **the repo is local-only — nothing is pushed.** Both are on you:

```bash
gh repo create meetly-ai --public --source=. --push
```

Then deploy `frontend/` to Vercel with `VITE_API_URL` set to the API origin, and the repo to Render, setting `CORS_ORIGINS` to the Vercel origin.

## 6. Routes worth opening first

`/` → `/meetings/4` (the eight-person call) → `/share/demo-clip` (permanent seeded share link) → `/search?q=pgvector`.

## 7. Limitations

- **No summary→transcript citations.** The biggest gap. Doing it properly needs segment ids carried through the summariser; fuzzy-matching summary text would produce confident jumps to the wrong moment. I left it out rather than ship a wrong one — same reasoning that made me re-anchor the seeded highlights to quotes after catching them landing on wrong lines.
- Keyword search only, no semantic. No auth. SQLite on Render's ephemeral disk resets on redeploy.

**One correction worth flagging:** late in the build I thought the `Stop` capture hook was broken — one prompt, zero responses. It wasn't. This whole build was a single uninterrupted turn, so `Stop` had never fired. While chasing it I ran the hook by hand and it wrote a mid-turn snapshot as a `RESPONSE` entry, which would have blocked the genuine one; I removed it and wrote the whole episode into `CAPTURE-TEST.md`. The real fix that came out of it: capture errors now go to `.claude/capture-errors.log` instead of being swallowed by a bare `catch {}`.

Still outstanding for you: push the repo, deploy both halves, and record the walkthrough with your camera on.
